# IBM BOB — MASTER DEVELOPMENT PROMPT
## PROJECT: MLForge
### AI-Assisted No-Code Machine Learning Learning Platform for Beginners
---
# LAYER 1 — ROLE & CONTEXT
You are an experienced **Full-Stack Engineer, Machine Learning Engineer, and Educational Technology Product Architect**.
You are helping me build a web-based educational platform called **MLForge**.
MLForge is a **No-Code Machine Learning Learning Platform for beginners**.
The primary goal is to allow users who have little or no programming experience to understand the fundamental machine learning workflow by visually configuring a machine learning model, training it remotely, evaluating its performance, making predictions, and exporting the trained model.

The target users are:
* Machine learning beginners
* Students
* University students
* Non-programmers interested in machine learning
* Users who want to experiment with neural networks without writing Python code

The core educational workflow is:
**Learn → Choose Dataset → Design Model → Configure Training → Train → Evaluate → Predict → Export**
The application should teach users not only how to obtain a prediction, but also how dataset selection, neural-network architecture, hyperparameters, training behavior, and evaluation metrics affect a machine learning model.

### IMPORTANT ROLE OF IBM BOB
IBM Bob is ONLY the **development and coding assistant used by the developer to build MLForge**.

IBM Bob is NOT a component of MLForge.
Do NOT implement IBM Bob as:
* A chatbot inside MLForge
* An AI assistant inside the MLForge UI
* A backend API
* A runtime service
* A model-analysis service
* A user-facing feature
* A dependency required to run MLForge

The end user of MLForge should NEVER need access to IBM Bob.
The relationship is:
**Developer → IBM Bob → Generated/modified source code → MLForge application → End User**

IBM Bob should therefore focus on generating, modifying, debugging, and improving the actual MLForge source code.

# 2. DATASET SELECTION
Create a dataset selection interface.
The initial version should support at least:
* MNIST
The architecture should be designed so that additional datasets can be added later, such as:
* Fashion-MNIST
* CIFAR-10
* Other compatible image datasets

For MNIST, allow the user to select between:
### Binary Classification
Exactly two classes are selected.

### Multiclass Classification
Multiple classes can be selected.

The number of classes must be determined dynamically from the selected dataset/classes.

Display basic dataset information such as:
* Dataset name
* Number of classes
* Input image dimensions
* Number of training samples
* Number of validation/test samples
* Selected classes

The application must validate invalid dataset configurations before training.

# 3. NO-CODE MODEL BUILDER
Create a visual neural-network model builder.
The user must be able to construct a model without writing Python code.
Initially support these layer types:
* Conv2D
* MaxPooling2D
* AveragePooling2D
* Flatten
* Dense
* Dropout
* BatchNormalization

The interface should allow users to:
* Add a layer
* Remove a layer
* Reorder layers
* Configure layer parameters
* View the resulting architecture
* Validate incompatible layer configurations

Example configuration:
```json
{
  "layers": [
    {
      "type": "Conv2D",
      "filters": 32,
      "kernel_size": 3,
      "activation": "relu"
    },
    {
      "type": "MaxPooling2D",
      "pool_size": 2
    },
    {
      "type": "Flatten"
    },
    {
      "type": "Dense",
      "units": 128,
      "activation": "relu"
    }
  ]
}
```

The frontend should send this structured configuration to the backend.
Do NOT allow arbitrary Python code execution from user input.
---

# 5. REMOTE MODEL TRAINING
IMPORTANT:
**Training MUST NOT be performed using the user's local CPU or GPU through browser-based machine learning.**

MLForge should use a backend/remote training environment.

The browser should send:
* Dataset configuration
* Model architecture
* Hyperparameters
to the backend.

The backend should:
1. Validate the configuration.
2. Construct the Keras model.
3. Load the selected dataset.
4. Compile the model.
5. Train the model.
6. Record training history.
7. Evaluate the model.
8. Save the trained model.
9. Return the results to the frontend.

The initial implementation should prioritize a **free remote/cloud execution approach suitable for a prototype**.
Do not design the application around paid infrastructure.

Because free cloud resources are limited, implement appropriate limits on:
* Training duration
* Epoch count
* Model size
* Dataset size
* Concurrent jobs
---

# 12. EDUCATIONAL EXPLANATIONS
MLForge should explain machine-learning concepts throughout the workflow.
Examples:
### Conv2D
Explain that convolutional layers learn spatial patterns in images.
### Pooling
Explain that pooling reduces spatial dimensions while retaining important information.
### Flatten
Explain why feature maps are converted into a one-dimensional representation before Dense layers.
### Dense
Explain how fully connected layers combine learned features for classification.
### Dropout
Explain its role in reducing overfitting.
### Epoch
Explain what one epoch means during training.
### Batch Size
Explain how samples are grouped during training.
### Learning Rate
Explain how the learning rate controls the size of parameter updates.
These explanations should remain concise and beginner-friendly.
---

# 13. ERROR HANDLING
Implement graceful error handling.
Examples:
### Invalid architecture
Show:
> The current architecture is incompatible. Please check the layer order and dimensions.
### Training failure
Show:
> Training failed. Please review your configuration and try again.
### Remote service unavailable
Show:
> The remote training service is currently unavailable. Please try again later.
### Invalid image
Show:
> The uploaded image format or dimensions are not supported.
Never silently fail.
Never fabricate successful results.

# 14. RESPONSIBLE AI
MLForge is an educational experimentation platform.
The application must clearly state that:
* Results are educational/experimental.
* Predictions should not be treated as professional decisions.
* Users should avoid uploading sensitive personal information.
* Uploaded data should be handled with appropriate privacy considerations.
* The system must distinguish actual training results from demonstrations or mock data.
Do not position MLForge as a professional medical, financial, or diagnostic system.
